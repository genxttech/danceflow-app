# TW-4 R1: brand submission runner (local build)

Status 2026-10-15: built and validated locally in `C:\Dev\studioapp-tw4a` (branch `twilio-tw4a-onboarding-foundation`). **Uncommitted. The R1 migration is NOT applied to shared DEV or PROD** (it is applied only to the local QA stack). **No Twilio call was made and none can be made from DEV, preview or tests.** Owner decisions applied: ConfiDance pilot in the parent account (pilot-scoped exception to D2), Standard brand + `MIXED`.

## What R1 does (and does not)
Runs the approved Twilio sequence for ONE studio, up to and including the **Brand**, then follows the brand's status:
`S1` profile, `S2` business EndUser (the only place the EIN is decrypted), `S3` representative, `S4` address, `S5` address document, `S6–S9` assignments (incl. the ISV Primary profile), `S10` evaluate, `S11` submit, `T1` A2P TrustProduct, `T2` A2P EndUser, `T3–T4` assignments, `T5` evaluate, `T6` submit, `B1` Brand (**fee-bearing**). On brand approval: state `service_setup`, EIN ciphertext erased, TW-3 row mirrored as brand approved (the studio is **not** approved for sending).
Not in R1 (R2 and later): Messaging Service, campaign, number purchase, Advanced Opt-Out step, Event Streams, cron, emails, subaccounts. Nothing here can send SMS.

## Safety properties (each is a test)
No Twilio access outside `real.ts`; the real adapter cannot be constructed unless the deployment is **production** AND `TW4_ISV_REAL_CALLS=on`; the fake is refused in production. A succeeded step is never re-run; an in-flight/unknown step is reconciled against Twilio first (profile and trust product by FriendlyName, brand by bundle linkage). The paid brand needs a platform-admin confirmation on every attempt (recorded on the ledger) and is never re-created after an ambiguous outcome (it becomes an `exception`). Transient failures stop with `unknown_outcome`; nothing retries automatically. Noncompliant evaluations never reach submission (`needs_info` with the wizard field highlighted, or `exception`). The ISV Primary profile must be `twilio-approved` before anything is created. The EIN is read once, decrypted inside S2, and appears in no ledger row, audit row, result or other call. Leases (database) stop overlapping runs.

## Security review of R1 (2026-10-15, Opus, read-only) and fixes (local)
The review found no blocker for applying the migration to DEV and four P1s that block enabling the real adapter in PROD. All four P1s and the SQL P2s are fixed locally (the migration was rewritten in place; it had never been applied to a shared database).

**Current hashes:** migration `63ba6947ab87…`, rollback `5d0f759c4e15…`, SQL suite `2753a08ba013…` (56 checks). (The earlier `ab46edbc2a74…` text above is superseded.)

- **P1-1 unclear brand-create result could allow a second paid brand.** Only a parsed 4xx (or bad credentials) is now recorded as a definite failure. A network error, timeout, 429/5xx, unreadable body, SID-less 2xx, or any unrecognized error is `unknown_outcome`, reconciled before any retry (`real.ts` classification + `runner.ts`). The runner now ALWAYS looks up an existing profile/trust product/brand before creating one, not only on reconcile; several matches is an exception, a failed lookup stops the run.
- **P1-2 resubmission bought a second brand.** `tw4_runner_begin_step` refuses the paid step (SQLSTATE 55000) when the registration row already holds a brand, or when any earlier B1 attempt for the studio (another generation or onboarding) is not a definite failure. The runner turns that into an `exception` (`brand_exists`). A human marks the old attempt failed only after confirming at Twilio that it produced nothing.
- **P1-3 the env switch is not a runtime switch.** New database kill switch: `studio_sms_runner_windows` + `tw4_runner_set_window` (platform admin, 1–72 hours, 0 closes, reason, audited). `tw4_runner_claim` in mode `run` refuses (SQLSTATE `TW001`, outcome `runner_closed`) outside an open window; mode `refresh` (GET-only) needs none. Platform panel: "Runner window" form. The env gate stays as a second condition and now also requires `NODE_ENV=production` (a local `next dev` with pulled production variables is refused).
- **P1-4 mock brand treated as real.** The ledger records `mock`. A mock brand is never mirrored into the registration and cannot approve the onboarding (SQL refuses both; runner reports `mock_brand`). Consequence: a mock dry run on a studio blocks a later real brand for that studio (the one-brand guard), so **run the dry run on a separate, non-pilot test studio**.
- **SQL P2s:** the fee flag is derived from the step in SQL (a caller cannot claim "not paid" for B1 or "paid" for another step); `finish_step` only finishes an OPEN step (a succeeded step and its sid are final); the lease is renewed on every step; `tw4_runner_get_ein` takes the acting admin (must be a platform admin) and the read is audited with that admin; a `stale_exception` purge removes EIN ciphertext from an onboarding left in `exception` for 30 days (forward fix of the 4A purge functions; the rollback restores them verbatim).
- **TS P2s:** every Twilio request has a 20 s timeout and the body read is inside the guarded exchange; profile/trust-product lookups follow Twilio's own next-page links (host-checked, 5 pages); the Primary-profile preflight also requires the Primary policy (`TWILIO_ISV_PRIMARY_POLICY_SID`, now required); the key id beside the EIN token must equal the one inside it; the fake redacts the EIN unless capture is enabled for a test, and is allowed only against a loopback database (so it can never write fake SIDs into shared DEV); `import "server-only"` on `real.ts`, `config.ts`, `factory.ts`, `ein.ts` (vitest aliases the marker).

**New validation:** SQL R1 suite 56 checks, 20 mutation probes each fail the suite (one equivalent: the brand-overwrite guard is now redundant with the recorded-brand check); TW-4A suite still 89; rollback then re-apply clean. TS: runner tests 42 (10 mutation probes, all caught after adding a key-id test), adapter/config/factory 40, platform action + panel 25+. Real-schema integration (local QA stack): R1 11 tests + 4A 14 tests pass. Full vitest 404 files / 6406 tests; tsc 0; ESLint clean.

**Accepted residuals (documented, not fixed):** a retried S2 can leave an orphan EndUser (Twilio offers no friendly-name filter for EndUsers; it holds the same data Twilio already holds for the real one); a Server Action has no `maxDuration` hook (the 20 s per-request timeout plus per-step lease renewal bound a run); Vercel freezes env vars per deployment, so `TW4_ISV_REAL_CALLS` must be unset again and redeployed after the run, and the database window is the real kill switch; nothing stops someone running a local production build against pulled production variables (process rule: never pull production env).

**New environment variable for the real run:** `TWILIO_ISV_PRIMARY_POLICY_SID` (the Primary profile's policy; read it from `GET /v1/Customer​Profiles/{primary}` together with the two policy SIDs the runner needs).

**Verdicts from the review:** applying the (now revised) R1 migration to shared DEV: GO. Enabling the real adapter in PROD: NO-GO until a Twilio mock-brand dry run on a non-pilot studio has been done and read.
