|---|---|---|---|

Implemented locally (uncommitted), all behind the existing gates:

- **Harness.** The real-adapter harness refuses a config without a key or one that still carries a token; the network fence removes the ambient `TWILIO_AUTH_TOKEN` from the process in real mode.

Stage B still stops at S10 positionally (runner), by ledger precondition (stage wrapper) and at the network layer (the fence allows only GETs and the draft-creating POSTs, and never a `Status` field). Stage C keeps its own token (now bound to mailbox, key SID and Primary profile too).
- **Cleanup** refuses to delete the ledger (the only inventory of created Twilio SIDs) unless `--evidence-file <new file>` saves it first. Runs that do not end where the stage should exit with code 1.
**Provider support for key-signed writes:** documentation supports it (Standard keys: "all API resources except Accounts and Keys"; Twilio's own Trust Hub sample code constructs its client with an API key, secret and Account SID) but it is **unverified live**; Stage A proved reads only. ## 10. Launcher review round (independent Sonnet review + re-check): findings fixed
No P1 in either pass. Five P2s were fixed and re-verified: (1) `cleanup` requires `--evidence-file` whenever ANY ledger row exists (rows without a SID still carry the friendly name that locates an orphaned resource) and writes it with `wx` before deleting anything; (2) a failed or half-finished seed is detected through the harness's marker file, cleaned up in the dry run and explained (with the exact cleanup command) in real mode; (3) the database containers are pinned to the local QA stack names, `DOCKER_HOST` is refused and the active docker context must point at a LOCAL engine (`npipe:////./pipe/...` or `unix:///...`; Docker Desktop's local context is called `desktop-linux`, so the endpoint is checked, not the name); (4) exit codes: the harness exits 2 only for refusals/failures before any stage started and 1 afterwards; the launcher treats any code other than 0/2 (including Ctrl-C and kill statuses) as "Twilio calls may have been made"; (5) an unreadable inventory is no longer reported as "no resources", and no cleanup is offered then. Also: `-AuthMinutes` bounds, strict-mode-safe reads, unsafe business-path characters refused, plaintext environment tables nulled, an EIN clipboard note, a non-zero exit when cleanup fails, an Interrupted-by-Ctrl-C message, and the dry-run self-test now verifies the REASON for the authorization refusal (a person at an interactive terminal is required), which exposed that an earlier version of the check could pass for the wrong reason.
Accepted, by design: `requireHuman` is a procedural gate (the typed phrase) and the HMAC secret is a local key file, so someone with file access could mint a token; the real barrier is that the Standard API key secret exists only in the operator's typed input. The stage token and expiry are visible on the node command line (useless without the key secret; replayable until expiry, at most 120 minutes).
Test status: 22 non-interactive launcher cases, 9 interactive scenarios, 12 direct harness checks (exit codes, cleanup evidence, container pin, DOCKER_HOST), Stage A regression (10 + 10), tsc / ESLint / 351 unit tests; zero blocked network attempts under the tripwire.
