## Overview

Portal schedule requests let clients ask for a lesson time. Unless the booking mode is Instant, nothing is added to the calendar until staff approve.

Outside Instant mode, staff review each request before it is scheduled. That keeps the studio in control of availability, instructor assignment, room usage, and final scheduling.

## Where booking requests come from

Booking requests can come from:

- Client portal schedule request pages

Portal schedule requests are usually for existing clients who already have portal access.

Public inquiry forms do not feed this queue. An inquiry from your public studio profile arrives as a new lead for your team to follow up.

## Where staff reviews requests

Go to **Self-service Requests** in the menu (the **Schedule Requests** page). The **Booking Requests** button on the Schedule page opens the same page.

The request queue has tabs for pending, executed, declined, and failed requests.

Each request shows the client name, status, action (book, reschedule, or cancel), booking mode, lesson type, requested time, instructor, room, submitted date, and the client's note if there is one.

## Statuses

Booking requests use these statuses:

- **Pending**: needs staff review
- **Executed**: approved and carried out on the schedule
- **Declined**: not scheduled
- **Failed**: the request could not be carried out

## Best practice

Review pending requests daily. If a request works, approve it so the schedule is updated. If it does not work, decline it with a note and follow up with the client using another available time.
